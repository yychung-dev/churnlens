## M0|環境建置與資料載入

### [M0-1] 結論：`data/raw/` 不進版控，README 附下載指引。

- 理由一：公開資料集再散布屬授權灰色地帶，附取得指引是資料社群通行做法。
- 理由二：「不隨意複製散布資料」是資料治理意識。
- 理由三：保持 repo 輕量，clone 快速。
- 否決替代方案：「直接 commit CSV (方便 clone 即用)」，便利性不足以抵銷上述三點；可重現性改由下載指引 + 載入腳本保證。

### [M0-2] 結論：版控採 main / develop / feature 三層流程；feature 完成先進 develop，模組驗證標準全數通過後才由 develop 進 main。

- 理由一：main 必須隨時保持「觀看者任何時刻點進來都是完整穩定而非半成品的狀態」，需要 develop 作為整合緩衝層。
- 理由二：三層流程與業界多人協作慣例一致，單人專案沿襲此工程紀律，不只追求最小可行的版控。
- 理由三：「確認無誤」的明確定義是，merge 進 main 時，該模組驗證標準全數通過 + 補齊決策日誌。
- 否決替代方案：「簡化 feature branch(feature 直接 merge main)」，失去整合緩衝，以標準流程保證 main 的穩定性。
- 補充：merge 一律 `--no-ff`，保留各模組分支的歷史結構，使 commit 圖可讀出專案的模組化開發節奏。

### [M0-3] 結論：資料一律分層：檔案系統分 `data/raw/` 與 `data/processed/`，資料庫分 `raw` 與 `clean` schema；原始層資料唯讀，所有清洗加工都只寫入新的分層。

- 理由一：可追溯，任何分析結果被質疑時，能從原始層重跑整條清理流程，定位問題出在哪一步。
- 理由二：可重現，「原始資料 + 清理腳本 = 分析用資料」成立，任何人都可重建 clean 層。
- 理由三：此即資料工程 staging 概念的縮影，與後端「不直接改 prod，要以 migration 留下變更紀錄」的精神相通。
- 否決替代方案：「單層，直接在原始資料上清理」，雖能省一次複製流程，但清理是有破壞性的操作，若出錯就不可逆，喪失『原始真相』的原點。

### [M0-4] 結論：raw 層所有欄位用 TEXT 型別，不在載入階段做任何型別轉換。

- 理由一：載入永遠不會因型別問題失敗(髒值、格式異常照單全收)，重點在「資料能進來」。
- 理由二：raw 層的職責是保留原貌；型別轉換本質上是一種清理，應在 clean 層明確決策、執行並留下紀錄。
- 理由三：M1 稽核時才知道每欄真實的髒法，若現在先定型別，是在資訊不完整時就做不可逆的假設。
- 否決替代方案：「載入時直接定義正確型別」的狀況有兩個問題，(1)若任一列有髒值就會導致整批載入失敗；(2)把資料清理混入資料載入流程中，是違反分層架構原則([M0-3])。

### [M0-5] 結論：PostgreSQL 容器不掛 volume，容器刪除即清除資料，停止/重啟容器則不影響。優點：資料隨時可依 CSV + 腳本重現，資料可重現性由自動化 pipeline 腳本保證，不由容器狀態保證。

- 理由一：本專案真實資料隨時可由 raw CSV + sql/ 腳本重現，資料庫隨時都能以三條指令在 15 分鐘內重建，符合 M0 驗證標準「砍掉容器就能重建」。
- 理由二：所有變更都寫在有版控的自動化 pipeline 腳本裡。不依賴容器內部狀態，也避免「在資料庫手動修改」的情形，保證專案在任何電腦執行都有相同結果。
- 否決替代方案：「掛 volume 持久化」，這是多人或正式生產環境的正確做法。本案是單人分析的環境，重點是「自動化腳本的維護」，不是依賴資料庫的存檔。
- 2026-07-21 實證：Docker Desktop 關閉導致容器停止，docker start 即可復原 (將既有容器重新開機，並經 SELECT指令 驗證原資料仍完整存在)；即使容器被刪，README 路徑可於 15 分鐘內重建。本則決策所承諾的可重現性，已經真實案例驗證。

### [M0-6] 結論：依然在 raw 層載入「陷阱一的兩個欄位 (模型輸出欄)」(改成較短名稱如 nb_classifier_prob_1)，刪除這兩欄的動作留給 clean 層執行。

- 理由一：維持「raw 層保留原貌」的原則([M0-3])，「這兩欄該刪除」屬資料清理的決策，應發生在 clean 層並記錄理由。
- 理由二：縮短欄名是安全的，因為 \copy 語法是「按欄位位置對齊」，與欄名無關；且原始欄名(Naive*Bayes_Classifier*...)過長、難閱讀，將其改短是為了提升「開發的可讀性」，不改動資料內容。
- 理由三：保留這兩欄，明確呈現「data leakage 的處理」，在 raw 層看得到這兩欄 → 在 clean 層刪除這兩欄 → 在日誌記錄刪除理由，形成完整的稽核軌跡。

### [M0-7] 結論：批量載入原始資料採 `\copy` + 手寫 DDL；M1 起 Python pipeline 寫回 clean 層採 pandas `to_sql`。依不同層 (raw、clean) 的職責選擇不同工具： raw 層的核心價值是「人工審核資料的載入，防止髒資料破壞結構」，clean 層的核心價值是「與 Python 清理流程自然整合」。

- 理由一(型別控制)：`\copy` 進全 TEXT 表，不做型別轉換，型別決策延後到稽核之後(M1)的 clean 層才明確執行；`to_sql` 由 pandas 自動推斷型別，導致髒資料在未經稽核前被盲目定義型別。實測佐證：同一份 CSV 兩種方式各載一次(筆數皆為 10,127)，`information_schema.columns` 確認 `\copy` 版 `customer_age` 為 `text`、`to_sql` 版為 `bigint`。
- 理由二(控制資料載入方式)：M0 實測發現 `to_sql` 的自動化不只發生在型別，欄名長度、欄名大小寫也直接依照 CSV 原始格式，兩者都造成真實問題(詳見 [M0-Issue1]/[M0-Issue2]：63 字元截斷導致建表失敗、大寫欄位名導致後續查詢漏抓資料)。`to_sql` 自動化載入的每一個環節：欄位名、大小寫、型別都未經人工審核而出錯，**用 `\copy` + 手寫 DDL 則能自己控制資料依正確方式載入** 。
- 理由三(效能與可擴展性)：`\copy` 走 PostgreSQL 二進位資料流通管道，不經 Python 轉換；`to_sql` 則需經 Python 將資料逐批拆解並組裝成龐大的 INSERT 字串。資料量大時兩者的載入速度可相差高達數十倍，可能造成效能瓶頸。雖本案只有 1 萬筆資料時感受不明顯，但考慮可擴展性，raw 層載入應優先選擇效能好的`\copy` 方法。
- 理由四(to_sql 的正確應用)：clean 層與後續小結果表(如 M5 分群預測結果)本來就以 Python DataFrame 的形式存在，用 `to_sql` 寫回資料庫最自然；且前面已在 Python 中把資料型別整理好，此時讓 pandas 自動推斷型別反而是優點，省下手寫建表指令的力氣。
- 代價(多寫 DDL 的代價)： `\copy` 需多花時間手寫 DDL 腳本建立空資料表，且從 raw 轉換到 clean 層時需在 SQL 裡一個欄位一個欄位手動寫出轉型別語法。但優點是「每行轉型別的規則和邏輯都會被清楚記錄，方便追溯與查核」。
- 否決替代方案一：「全程用 `to_sql`(含載入原始 CSV 檔)」，等於把欄位名、大小寫、型別的決定權交給 pandas 自動推斷與處理，「把控制權交給工具猜測推斷」對髒資料而言不安全；且大資料量情況下`to_sql`效能不佳、速度慢；M0 實測更因欄位名問題導致建表失敗。
- 否決替代方案二：「全程用 `\copy`(含 clean 層寫回)」，clean 層已用 Python 算好乾淨結果存在 Python 記憶體中，若要用 `\copy` 寫入資料需先把資料存成 CSV 再載入，多一次中介檔案與人為操作步驟。對已處理且可控的資料直接用 `to_sql` 寫回去就好，沒必要繞遠路用 `\copy` 。

### [M0-Issue1] 因 PostgreSQL 欄位名過長，pandas `to_sql` 發生字元截斷，導致欄位名衝突。

- 現象：`to_sql` 寫入時報 `DuplicateColumn` 錯誤，問題點在「自動生成的 CREATE TABLE」。
- 成因：CSV 末兩欄原始欄位名約 130 字元，只有末尾的(`_1`/`_2`)不同；PostgreSQL 的欄位名長度上限為 63 bytes 因此自動截斷超過的字元，截斷後兩個欄位名完全相同，進而發生欄位名稱相同的衝突報錯。
- 解法：寫入前將末兩欄改名為 `nb_classifier_prob_1/2`(比照 `00_ddl.sql` 的人為決策)。
- 收穫：`\copy` + 手寫 DDL 不會出這種錯，原因是「欄位名在 DDL 階段經過人為決策」，符合 [M0-7] 「人工審核決策」結論。

### [M0-Issue2] `to_sql` 直接依 CSV 原本的大寫欄位名套用，導致元數據（Metadata）檢索失效 (`information_schema` 比對查詢時漏抓資料)

- 現象：以 `column_name = 'customer_age'`(全小寫)查詢型別比對時，只回傳 `\copy` 版結果，`to_sql` 版則檢索不到。
- 成因：PostgreSQL 對未加雙引號的識別字 (Identifiers) 一律自動轉小寫，但 `to_sql` 以雙引號原樣建立 CSV 的 `Customer_Age`(大寫)，全小寫條件因此比對不到大寫的欄位名。這類欄位將來每次查詢都必須寫 `"Customer_Age"` (帶雙引號)，一旦缺少引號就報「欄位不存在」錯誤。
- 解法：比對查詢改用 `LOWER(column_name) = 'customer_age'`；治本的預防作法是「遵守識別字一律 snake_case 小寫的慣例」(手寫 DDL 已遵守此慣例，但 `to_sql` 不會自動把關)。
- 收穫：`\copy` + 手寫 DDL 靠人為決策把關，不會出這種錯，但 `to_sql` 自動化不會為這種命名慣例把關。

備註： DDL（Data Definition Language）是「定義資料庫骨架與結構」的 SQL 腳本。

### [M0-8] 結論： 資料庫連線設定改由 .env 管理 (python-dotenv)，搭配 fail-fast 驗證與 singleton engine；程式碼中不保留任何連線的預設值 (eg. 資料庫密碼、資料庫連線網址)。

- 理由一：secrets 與程式碼分離是基本資安意識。.env.example 進版控作為設定範本，實際的 .env 納入 .gitignore。
- 理由二：採取 fail-fast 策略可降低除錯成本： 讓錯誤在 import 時就立刻浮現並附修正指引，而非等到連線時才失敗。
- 理由三：singleton 設計模式，確保整個專案只建立一個 engine。create_engine 內含連線池 (SQLAlchemy 在底層會自動啟動一個連線池管理員，預設容納 5 條連線的連線池)，若沒用 Singleton，每次呼叫 create_engine 都會在記憶體中建立一個新的連線池，多次呼叫就會重複建池，吃掉過多沒必要的連線資源。
- 否決替代方案：「直接把密碼寫在程式碼中 + 環境變數覆寫」雖能提升本機操作的便利性 (在沒設定 .env 時可自動使用預設值，且理論上線上環境可用環境變數「覆寫」掉預設值來做對應操作)，但這種便利性會讓開發者產生惰性，導致測試密碼留在版控中；而且，「將密碼與程式碼分離」是基本的資安紀律，不應依風險高低而妥協，所以本專案決定不在程式碼中留存密碼預設值。
- 影響：README 的重建流程新增一步 `cp .env.example .env`。

> 註一：金額欄一律使用可容納小數的型別 (Pandas 用 float64、PG 資料庫自動 mapping 成 DOUBLE PRECISION) (細節見註 3)
> (1)資料型別的訂定應反映欄位語意的可能範圍 (金額的業務本質是可以「有小數」的，不因樣本剛好無小數而限縮在整數型別；且稽核D雖在min、max、avg都得出整數，但可能有某些資料是小數，但計算 min、max、avg 時剛好都算出整數，除非對每一格都做嚴格的正則檢查是否無小數)
> (2)避免發生 astype 無聲截斷 (Silent truncation)(eg.在大多數 Pandas 版本與標準 Numpy 路徑下，可能在對 50.5 這種含小數的浮點數執行 astype("int64") 時，使用 truncate 向零取整成 50 且不報錯)

> 註二：稽核檔皆使用 numeric：較嚴謹 (E 區需精確到和 0.01 相比)、本案不影響效能 (極大量資料的統計運算時，效能才可能被影響。本案資料表不大，幾乎無效能差異)、一致性(在不影響效能的情況下，整份檔案都用 numeric 轉，具備一致性及可讀性)

> 註三：若用手寫 DDL 建表，金額欄慣例選 NUMERIC (精確十進位)；本專案做法是經由 to_sql 自動 mapping 所以落地為 DOUBLE PRECISION，雖不及 NUMERIC 精確，但 DOUBLE PRECISION 的精確度對分析情境的效果與 NUMERIC 相同，所以可接受。因為：切片統計(平均、分箱)、檢定、建模等運算的結論精度需求在小數 2~4 位，而 float64 的誤差在第 15~16 位有效數字之後，所以誤差雖然存在但不會影響分析效果。本案用 NUMERIC 或用 DOUBLE PRECISION 所得出的結果、模型係數、報表都會相同。(用 NUMERIC 和用 DOUBLE PRECISION 效果會不同的情境：如「會計對帳」(上一筆交易逐筆加總後，要求分毫不差地對平帳目，而此時浮點誤差可能會被累積到在結果上能看出來的位數，就必須用 NUMERIC))。

### [M1-1] 結論：三個類別欄的 'Unknown' 保留為獨立類別，不轉 NULL、不剔除。

- 理由一：實測 Unknown 占比：education 15.00%、income 10.98%、marital 7.40%，占比量不低，若剔除將損失上千樣本，削弱 M3 檢定力。
- 理由二：「不願透露/未能取得」本身可能與流失行為相關，若直接剔除，概念等同「假設 Unknown 是隨機缺失 (MCAR, Missing Completely At Random)」，但此假設無法驗證 (因為資料裡沒有任何欄位解釋「為什麼這格是 Unknown」)；因此，保留 Unknown 資料，讓這樣的資料成為可分析的訊號。
- 理由三：轉 NULL 會使這些列在分組統計中，被聚合函數在「無任何警示或報錯的情況下，排除在計算之外」，如此，分母會在沒被察覺的情況下變小；因此，保留 'Unknown' 這個字串類別，能使每張報表的分母都如實包含全部 10,127 筆樣本。
- 否決替代方案：「剔除 Unknown 列」：原因如上；「眾數補值(mode imputation)」：因為 Unknown 佔比太大，且無理由相信 Unknown 是隨機缺失的情境 (有可能是「不願透露」的訊號)。若直接「把 Unknown 格填上該欄出現最多次的值」，等同「憑想像製造假樣本」，對占比達 10% 以上的 Unknown 直接做眾數補值，會嚴重扭曲該欄分布。

### [M1-2] 結論：clean 層職責定為「修正錯誤」，不預做分析取捨；分析上需排除的正確資料(avg_open_to_buy、months_on_book 等)於 clean 層仍保留，之後再由後續章節明確排除並記錄理由。

- 理由一：clean 層是所有章節共同依賴的基礎資料，M2 切片仍需要 avg_open_to_buy 與 months_on_book；不該單獨因為 M4 這章的建模需求，就直接在 clean 層刪除(不該讓 M4 單獨章節的需求直接決定全案的資料內容)。
- 理由二：在哪個階段用不到特定資料，就在哪個階段做「排除資料」的動作，並且在排除當下「註明理由」，將來閱讀時就能同時看見「刪除動作及刪除理由」。本例要在 M4 做特徵選擇時排除，就在 M4 排除並記錄於該處，在同一層做決策和註明理由。
- 否決替代方案：「在 clean 層就直接刪除分析上有疑慮的欄」：這個動作不可逆(因為後續章節都以此 clean 層資料為基礎，若此處就刪除，後續章節直接無從判斷取捨和分析)，而且「資料錯誤」與「分析取捨」是兩種性質不同的決策，本案由 clean 層專門處理「資料錯誤」，「分析取捨」則由後續章節來做，才不會混淆。

### [M1-3] 結論：nb_classifier_prob_1/2 於 clean 層刪除。

- 理由：(1)此兩欄是上游原作者的模型輸出。原作者以本資料集訓練過一個預測流失的模型：訓練時，「attrition_flag(每位客戶的真實流失結果)」即為該模型逐筆根據相關特徵(features，如年齡、信用額度...)比對、預測後，最後用來校準自身預測結果的「答案(預測模型的標籤 label)」。原作者依前述特徵 + 標籤做完模型訓練後，得出該模型對這一萬名客戶的「流失預測機率」，並將此存回資料集，即為此兩欄內容。這兩欄的內容本質上是「看過答案(attrition_flag)後產生的猜測」，因此這兩欄內容與目標變數必然具高度相關性。若本案模型訓練時將這兩欄當成主要特徵，等同本案模型在訓練時間接偷看答案(data leakage)：本案模型會因其壓倒性的相關而依賴此兩欄、冷落真實行為訊號(如：不活躍月數、客戶年齡、信用額度等等特徵)，造成本案模型訓練/驗證階段評估分數虛高、卻無法泛化(generalize)到真實資料。此外，還有(2)部署問題：此兩欄只為這一萬人算過一次，真實世界的新客戶資料永遠不會有這兩欄，所以預測模型上線後甚至無法執行。這兩個問題都能單獨定性此二欄位是「資料汙染」而非有效特徵，符合 [M1-2] 定義的「錯誤」，故於 clean 層刪除。

- 完成「稽核軌跡 (audit trail)」(落實 [M0-6] 的設計)：raw 層可見兩欄 → clean 層刪除 → 本則日誌記錄理由。

### [M1-4] 結論：新增欄位(Boolean)「目標變數 is_churned(= attrition_flag = 'Attrited Customer')」，原欄位保留；pipeline 以三道 assert(筆數 10,127、主鍵唯一、流失率 16.07%)把關，任一關失敗就中止寫入資料庫。

- 理由一：Boolean 欄讓全案口徑落實為資料結構，AVG(is_churned::int) 就是流失率，避免發生「各章節各自定義流失率時，每次都重新用字串比對 (attrition_flag = 'Attrited Customer')，可能因打錯字等瑕疵發生計算錯誤 (而且程式不會報錯)，造成各處口徑不一致(口徑漂移 Metric/Definition Drift)」的風險。
- 理由二：assert 把問題定義書的「口徑定案」從「寫在文件裡的約定(無強制力)」變成「程式每次執行都自動檢查的規則(由程式自動檢查，避免人為疏失)」。如此，若未來更改清理邏輯時不小心動到口徑(例如：有人擅自更改已流失客戶的定義)，那算出的 is_churned 為 True 的比例就會與原本算好確定的 16.07% (定義在 validate 函式中)不同，就會發生 AssertionError → 程式中止 (pipeline 報錯)，透過這個檢查方式發現問題。(但若該口徑的更動是正式決策，流程就是：改問題定義書 → 記決策日誌 → 更新 validate() 裡的常數 → pipeline 恢復通過)
- 保留原欄：attrition_flag 是原始事實，is_churned 是衍生欄位；衍生欄位隨時能由程式重新算出，但原始欄一旦刪除就無法彌補。

### [M1-5] 結論：age×tenure 相關係數以 SQL 實測為 0.7889，取代網路社群流傳說法(0.79–0.97 不等，常見引用 0.97)作為全案依據。

- 影響一(M4)：0.79 的共線性仍足以使迴歸係數不穩，維持「二擇一」決策不變。
- 影響二(M2)：較 0.97 情境放寬：tenure 存在獨立變異，可謹慎用於切片，判讀時明示「帳戶年齡(tenure)與年齡混淆」的這個限制。
- 分析方法的原則：對任何未經官方文件證實的資料集特性，以自己的 SQL 實測為準；本次實測否定了最常被引用的數字，即體現這個原則的價值。

## M2|EDA 與流失切片

### [M2-1] 結論：切片分析由「假設樹」驅動：九項假設(H1–H9)於任何切片執行前事先指定並定案；未立假設的欄位列為「次要檢視清單」，切片時順帶檢視，但不對「所有欄位逐一兩兩組合、全部做一次交叉切片」，而是「由先立的假設引導，只對單變數表現最強的 3–4 個維度做交叉切片」。

- 理由一：19 個屬性的可能切法達上百種，若無事先以假設引導的切片，概念等同「事後撈取」；依顯著門檻的定義(α=0.05 代表無真實差異時，每 20 次比較中平均仍有 1 次是偶然顯著)，若大量切片，機率上必然出現一些「純屬抽樣運氣的差異」，無法從結果本身分辨真假。
- 理由二：「假設」在「事前指定」是 M3 檢定對 p-hacking 的主要防線；假設樹的 commit 時間早於所有切片結果的產生時間，「先假設、後切片」的時間順序可由版控證明。
- 理由三：假設分「行為假設(枝 1–3，可介入)」與「結構假設(枝 4，不可介入)」兩類，前者供後續挽留方案據以設計，後者用於資源分配。概念：「假設的分類」為後續章節(M5 的方案設計與資源分配)預作準備。
- 次要檢視清單的取捨：education_level、dependent_count、marital_status、card_category、customer_age、credit_limit 未立假設。
  - 原因：1.缺乏明確的業務邏輯可據以預期方向(如：教育程度與流失沒有直觀的因果關係)，或2.受既有限制約束(card_category 受小樣本限制：card_category 切出來 Platinum 那格只有 20 人，差異再大也不可信 [稽核 B]；customer_age 與 tenure 混淆：兩者相關係數 0.7889，customer_age 切出來看到的「年齡差異」可能是「tenure 差異」造成的誤會 [M1-5])。<br/>
  - 綜上所述，單獨立假設、單獨解讀的意義有限。因此，在「次要檢視清單」順帶檢視即可，若順帶檢視發現有異常，就標記為事後發現(探索性發現，exploratory finding)並記入日誌，從嚴解讀；若進入 M3 檢定，報告中須明示其為事後發現、非事前假設。
- 否決替代方案：「對所有欄位逐一切片，再從結果中挑出顯著者」：每多一次比較，就多一次偶然顯著的機會，據此挑出的「發現」無法與「純屬抽樣運氣」區分；且被挑出的假設是看完資料才產生的，若再以同一份資料檢定即為循環論證，無法在 M3 主張「假設」為「事前指定」。

### [M2-2] 結論：單變數(單維度)切片依欄位性質分三種切法:類別欄直接分組(B1)；低基數整數欄(僅 6–7 種值)逐值分組、不分箱(B2)；連續數值欄 NTILE(5) 等量分箱、附各箱實際範圍(B3)。全檔輸出格式統一為 grp / n / churn_pct / diff_pp。

- 理由一：分箱是當「數值種類多到無法逐一檢視」時的trade-off；低基數整數欄逐值分組即可完整呈現，若套用分箱，會把不同值混入同一箱，喪失逐值變化的解析度(如 H2 需要看 0→6 每一格的走勢,觀察「逐月變化的曲線形狀細節」)。
- 理由二：連續數值欄採等量分箱而非等寬分箱：本案金額類欄位資料分布右偏([稽核 D])，等寬分箱會使多數樣本集中在前幾箱、尾端箱樣本稀少，各箱流失率失去比較基礎 (等寬分箱的每箱金額範圍整齊，但各箱人數差異懸殊，喪失各箱族群流失率的可比性)；等量分箱保證每箱約 2,025 人，比較基礎一致。(「比較基礎一致」指：流失率的可靠度取決於分母大小，分母愈小、流失率愈易受隨機波動影響；等量分箱使每箱樣本數相同，各箱流失率的可靠度一致，不會出現「可靠箱與雜訊箱混在同一張表」的問題)
- 理由三：輸出格式統一，n (樣本數) 永遠呈現在表格上, 判讀時樣本數與流失率同時可見，才能在每一張表上執行「小樣本規則(如 Platinum n=20 就不下結論)」。
- 已知限制：NTILE 依筆數均分、不管值是否相同，同值客戶可能被切進相鄰兩箱。實測影響：total_trans_ct 最高頻率出現同值的該數值樣本數僅 208 人，箱界模糊度有限，故五分位判讀可信；avg_utilization_ratio 零值人口超過一箱容量(溢入第 2 箱)，第 1/2 箱邊界模糊, 故此欄改以「0 vs >0」二分切片重驗(見 [M2-6])。

### [M2-3] 結論：切片結果的證據強度分「四級判定(強支持/支持/弱訊號/無訊號)」，判斷標準是「假設的關聯方向(正相關或負相關)是否命中預期 × 與基準流失率的差距幅度(diff_pp) × 資料分佈曲線形狀 × 樣本數」四項綜合；各級對應不同處置決策:無訊號者不再深究；弱訊號者記錄形狀但不進 M3 檢定；支持與強支持則列入候選洞察。

- 理由一：切片產出十餘張表，若無統一判斷標準，逐表的取捨會無客觀標準與證據、流於個案感覺；四級判斷標準讓「哪些進檢定、哪些不進」有可檢視的依據。
- 理由二：弱訊號不進檢定的依據:檢定次數愈多，偶然顯著的累積風險愈高(多重比較成本)([M2-1] 理由一)，檢定名額應留給「確認為真就能行動」的訊號；弱訊號即使確認為真也難以轉為行動，就沒必要佔一個檢定名額(CP值低)。
- 弱訊號實例應用：H7(收入)判定弱訊號、不進檢定:全距僅 3.85 個百分點，且 U 型的兩端(高收入與低收入)流失成因高機率不同，一份挽留方案無法同時對應這兩種族群，即使假設檢定通過也無法轉為行動；將「中等收入最穩定」的形狀留作 M5 資源分配參考。無訊號實例應用：婚姻狀態、扶養人數、客戶年齡，曲線平坦貼近基準流失率，此維度無法區分高低風險客群，不再深究。
- 「事後發現」實例應用：教育程度僅最高學歷端偏高(突出主體 Doctorate 21.06%、+4.99 個百分點、n=451 ; 弱訊號 Post-Graduate +1.76 僅作旁證(diff_pp 幅度小),其餘四級平坦於 15.20–15.94%,貼近基準流失率。非「學歷越高流失率越高」的整體單調趨勢),依 [M2-1] 流程標記為事後發現、從嚴解讀。

### [M2-4] 結論：對「官方未提供計算公式」的欄位建立證據等級管理:欄位定義分「已驗證/推斷」兩級；凡成為候選洞察主角的欄位，其定義必須以 SQL 實證升級為「已驗證」，無法驗證者維持「推斷」並於判讀從嚴。

- 執行紀錄一：avg_utilization_ratio 原依社群說法推斷為 total_revolving_bal / credit_limit。H5 列入候選洞察第 3 順位後觸發「證據驗證升級條件」，比照稽核 [E] 的驗證方式實測(容差 0.001，取該欄最小刻度)，結果：mismatch = 0，全數 10,127 筆吻合 ➡ 「此計算公式的定義」實證成立，H5 的商業解釋(額度動用率 0 = 零循環欠款 = 無財務綁定)取得可靠依據。
- 執行紀錄二：total_amt_chng_q4_q1 依欄位名推斷為 Q4/Q1 消費金額比值，但 Q4 與 Q1 的原始金額不在資料集中，無法驗證，證據等級維持「推斷」，H3 判讀應保守。兩欄的驗證狀態差異將載明於 README 資料說明區。
- 理由：判讀的可信度應受限於「對欄位含義的掌握程度」(判讀的可信度取決於「對欄位定義的掌握程度(上位概念)」以及「計算是否正確(根據上位概念執行計算)」)；明文分級「欄位定義是推斷還是已驗證」，可防止推斷在多次引用後被誤當成事實。

### [M2-5] 結論：H6(客服聯繫次數)定位為「風險標記」而非「提前預警」：訊號本身是全案最強(0→6 次完整單調，1.75%→100%)，但「能否根據此訊號提前示警」仍有疑問，此判斷須有所保留，列入 M3/M8 方法限制。

- 理由：「聯繫多」與流失的關係存在兩種解釋：(a) 服務摩擦累積導致流失(前兆)；(b) 已決定流失者辦理註銷、爭議、餘額處理而產生大量聯繫(結果)。本案資料為單一時點快照，無法區分「每次聯繫發生在流失決定之前或之後」；6 次組 100% 全數流失的「完美」數字反而可能偏向解釋 (b) 的痕跡。
- 處置：仍可作為風險標記來使用(一樣可依此圈出名單)；但「發現此訊號時，距離客戶實際流失還剩多少可介入的時間」無法依本切片的資料判斷並做決策，必須在 M3 檢定與 M8 報告明示此限制。
- 價值註記：此為「訊號強度」與「訊號可行動性」分離的案例：與 H8(統計顯著但實務意義小)互為對照，兩者共同構成 M8 敘事中「不高估既有證據的效力(實際作用)」的素材。

### [M2-6] 結論：階段 C 交叉切片僅取四個訊號最強的變數(total_trans_ct、avg_utilization_ratio 以 0 vs >0 二分、total_relationship_count、contacts_count_12_mon)兩兩交叉，共 6 組；不對所有變數都做交叉。

- 理由一：兩兩配對的組合數隨變數量呈平方級(O(n^2)複雜度)成長(配對數:C的n取2 ➡ n(n-1)/2)，對所有變數都做交叉會產出大量無實質分析價值的表；只取單變數證據最強(訊號最強)的四個變數，讓交叉的每一組都有明確的驗證目的。
- 理由二：未能進入交叉切片的其他變數有其他安排：months_inactive_12_mon 與 total_trans_ct 同屬活躍度水位面向，「衡量同一面向的變數」互相交叉所得的資訊量低，所以取 total_trans_ct 為交叉切片變數代表；total_amt_chng_q4_q1 屬「變化方向」類的訊號，其任務(驗證 H1 的 Q2>Q1 假說)在階段 E 以分布比較處理，不佔交叉切片的名額。<br/>
  註：分布比較：並列比較兩組客群在該欄位的完整數值分布(直方圖/箱型圖)，而非只比平均數；若 Q1 與 Q2 的消費變化比分布形狀明顯不同 (eg.若Q2組的變化比整體明顯偏低，就支持「Q2是下滑途中的客群」這個假說)，即可驗證Q1和Q2這兩群人的性質不同(Q1客群雖交易筆數少但沒有下滑中、非流失前兆；Q2客群的交易筆數雖然比Q1客群交易筆數多，但消費下滑中表示Q2客群正在流失中)
- 理由三：階段 C 的兩個驗證目標:(1) 實測活躍水位類訊號的人群重疊規模(涉及挽留名單的去重、不重複編列挽留預算與客戶體驗)；(2) 檢視是否存在交叉後特別突出的組合客群，供 M5 挽留名單與 M4 特徵選擇參考。
- 附帶決策：H5 訊號以 0 vs >0 二分重驗(理由見 [M2-2] 已知限制)；credit_limit 的獨立性(是否為收入效應的影子)以「低額度 × 各收入組」交叉驗證(待驗證清單 #4)。

## M3|假設檢定

### [M3-0] 結論:M3 只對四個事前指定的對象做檢定:H6(卡方獨立性檢定)、H4 與 H8(兩比例 z 檢定)、total_trans_amt(Mann-Whitney U 檢定);候選洞察清單 v2 其餘條目與事後發現二則標記為「未檢定,列為觀察」。四個檢定合併採 Bonferroni 校正(α = 0.05 ÷ 4 = 0.0125)。

- 理由一(檢定名額與多重比較):檢定次數愈多,純靠抽樣波動得到顯著結果的累積機率愈高([M2-1]),名額應依 [M2-10] 的排序,留給「檢定結果會直接影響後續決策」的訊號:H4 影響 M5 名單條件與深化策略、H6 影響 M5 預警規則、total_trans_amt 影響 M5 價值軸;H8 另作為「統計顯著 vs 實務顯著」的示範案例。低活躍(diff_pp +15~+21、n=4,165)、零動用(+20.08、n=2,470)、旗標命中數分層與極高風險組合格的 diff_pp 幅度與樣本規模,已使檢定結果毫無懸念,對這些項目做檢定不會改變任何決策;這些項目真正待回答的問題是「訊號之間的交互作用」,此問題應由 M4 的多變數模型以交互項處理,不是兩兩檢定能回答的。
- 理由二(方法覆蓋):流失分析的假設檢定有三類常見情境:多類別與二元結果的關聯(卡方)、兩組比例比較(兩比例 z)、兩組連續數值比較且資料右偏(右偏資料採「非參數方法」);四個檢定對象依資料型態各對應一類,使 M3 涵蓋全部三類檢定,且 total_trans_amt 的右偏形狀已於 notebook 02 Cell E-7 以分布圖確認,「非參數方法」的選擇有「形狀證據的支持」。
- 否決方案:(1) 主力層與中段層全數檢定(八條以上):多數結果可預知,全做檢定只會增加多重比較成本;(2) 檢定事後發現二則(Doctorate、Unknown × 低額度):其假設由本份資料產生,若再以同一份資料檢定屬循環論證,依 [M2-1] 只能列為觀察,待取得新樣本資料再驗證。
- 檢核:若把 Bonferroni 的除數取為候選池全部的九條假設(α = 0.05 ÷ 9 ≈ 0.0056),本模組四個檢定的 p 值仍全部遠低於此門檻(最大者為 H8 的 0.00018),因此,檢定對象的挑選方式不影響任何結論。此對照列出的目的是揭露「挑選標準即使被質疑為偏向強訊號,也不影響任何結論」。
- 細節:notebook 03 第 1 節(檢定範圍、四個檢定對象的來歷與目的、兩層防線);待驗證事項 #12 於此結案。

### [M3-1] 結論:M3 不另開 SQL 檔;檢定分組全部沿用 M2 定義:H4 沿用階段 C 的淺關係旗標(total_relationship_count ≤ 2 vs ≥ 3),H6 沿用階段 B 的逐值分組(0–6 次,七組不合併),H8 沿用性別欄位。

- 理由一(不開 SQL 檔):本模組的資料查詢只是「從 clean.customers 讀取四個欄位」,檢定所需的輸入資料(T1 的列聯表、T2/T3 的兩組人數與流失人數、T4 的流失組與留存組各自的交易金額數值序列)都在 Python 端組成,沒有「值得獨立可重現的分析邏輯」;硬開一個 SQL 檔會使「SQL 檔負責查資料庫、notebook 負責判讀」的分工失去意義。目前規劃 M5 的分群矩陣會透過 sql/04_segment_matrix.sql 檔案執行。
- 理由二(H4 沿用旗標):檢定的分組必須等於 M5 名單的圈選條件,否則檢定通過也不能直接支持名單;界線「≤2」來自階段 B 逐值分組的實測斷點(2 項產品客戶的流失率 27.84% → 3 項產品客戶的流失率 17.35%,[M2-7])。
- 理由三(H6 七組不合併):H6 的證據價值在整條曲線完整單調(1.75% → 100%),若合併為兩組,會失去此資訊;且若將合併界線訂為 ≥4 次,這個界線正是 M5 尚未定案的預警線(待驗證 #10-a),檢定不宜預先綁定。檢定是否成立的「前提檢查」也有通過(14 格期望人數最小 8.7,高於 5),所以不需合併小組。
- 細節:notebook 03 Cell M3-1、M3-4(讀取)、T1 與 T2 方法段。

### [M3-2] 結論:多重比較校正採 Bonferroni(α 除以檢定次數 4,門檻 0.0125),不採 Holm 法或 FDR 法。

- 理由:Bonferroni 的代價是門檻變嚴後假陰性上升,在「真實差距不大」的情境可能錯過真訊號;本案四個檢定的差距都很大(H4 差 13.75 個百分點、H6 各組流失率自 1.75% 至 100%、total_trans_amt 中位數相差 1.76 倍),p 值最大者僅 0.00018,無論門檻是 0.05 或 0.0125,都不改變任何結論,門檻變嚴幾乎沒有代價;換到的好處是「四個結論合計的假陽性機率被壓回 5% 以內」,以及「這個方法可對非技術專業的決策者用一句話清楚說明」。
- 否決方案:Holm 法、FDR 法:用在「檢定數多且差距小時」,優點是「較不容易錯過真訊號」。但本案不符合此情境,且採用此二方法對業務單位的解釋成本較高。
- 限制:若後續模組(如 M6 同時檢定主指標與多個護欄指標)遇到差距較小的情境,應重新評估校正方法,不沿用本則決策。

### [M3-3] 結論:total_trans_amt 的兩組比較以 Mann-Whitney U 檢定為判讀依據,Welch t 檢定只列為對照。

### [M4-2] 結論:模型 B 與 C3-b 規則基準的比較以「固定名單規模,比精確率」為主(名單規模取在測試集上, C3-b 規則命中 ≥3 的 178 人與命中 ≥2 的 703 人),平均精確率(AP)與 precision-recall 曲線為輔;不用準確率;結論須在五個不同 random_state 的切分下皆成立(模型高出 C3-b 規則 5 個百分點以上)才採信。

## M5|風險 × 價值分群與挽留策略

### [M5-0] 結論:M5 以規則式分群(以分析者明確定義的條件分格:風險軸為旗標命中數、價值軸為交易金額三分位)建立挽留名單,k-means 只作對照、不將 k-means 分群結果用來圈選挽留名單。

- 理由一(已驗證的訊號比相似度分群更有依據):M2 至 M4 已經找到並驗證了與流失直接相關的四個旗標,用這些訊號分群,比讓演算法依客戶屬性的相似度分群更有依據;規則式分群的每一格定義可讀性高,可以直接寫成名單條件交給業務單位執行,也容易維護(只要「欄位定義」不變,「規則」就不變)。
- 理由二(k-means 的兩個缺點):(1) k-means 分群時完全不使用 is_churned (「是否流失」這個欄位),分群標準是「客戶彼此像不像」(用行為變數描繪客戶輪廓),不是「客戶會不會流失」,因此分出來的群不保證與流失有關,必須事後算出每群的流失率才能判斷;(2) k-means 群的定義是「離哪個群集中心最近」,群是「由七個變數一起計算距離決定」,沒有任何一個單一變數的門檻可以直接寫出來去代表這個群。業務單位若要明確圈選 k-means 分群出的某一群客戶,只能另外看群的平均輪廓去另外「寫一組近似的門檻規則」來說明這個群,概念等同「又回頭做規則式分群」。
- 檢核(notebook 第 7 節實測):k-means 在不看是否流失的情況下,分出的 A 群(2,658 人、流失率 42.1%)涵蓋「矩陣命中 3+ 客戶層」的 93%、「矩陣命中 2 客戶層」的 53%,證明「矩陣的分層」不是分析者主觀設定,而「是資料本身就有的結構」;但 k-means 四群的區分力(流失率 2.7% 至 42.1%)低於矩陣 12 格的區分力(0% 至 88%),且 k-means 的群無法直接寫成名單條件,所以最後決定「圈選名單的分群方式以矩陣為準」([M5-4])。
- 適用情境:規則式矩陣適合「已經知道哪些訊號與流失相關、且分群結果要直接交給業務單位執行」的情境;k-means 適合「還不知道訊號、想先看客群有沒有自然結構」的探索階段,或「沒有目標變數」的情境。

### [M5-1] 結論:矩陣兩軸定義如下。風險軸沿用 C3-b 規則的旗標命中數,四個旗標等權重、不加權,命中 3 與命中 4 合併為「3+」,分為 0 / 1 / 2 / 3+ 四層(流失率 1.34% / 8.68% / 36.72% / 82.89%);價值軸以近 12 個月交易金額(total_trans_amt)依人數切成三等份(NTILE(3)),邊界 2,567 元與 4,476 元,作為客戶價值的代理變數。風險軸不使用模型 B 的機率分數。

- 理由一(風險軸不用模型 B 的機率分數):模型 B 的精確率高出規則 7 至 9 個百分點(M4 第 7 節),但 (1) 規則的每一格都能寫成明確條件,業務單位可以直接執行與維護,模型 B 要每次重算 27 個特徵並套用模型,且其係數不能翻譯成規則;(2) 本資料集沒有挽留成本欄位,無法證明多出的 7 至 9 個百分點值得付出維護模型的成本;(3) 決策的可逆性:先用規則圈名單,之後仍可改用模型 B,不需重做分析。模型 B 的定位是「升級選項」,切換條件於 [M5-3] 定案。
- 理由二(等權重、不加權,待驗證事項 #26 定案):M4 模型 A 就是加權版的命中數,測試集結果顯示加權版與等權重版的名單品質相當(178 人名單 86.5% vs 84.3%,五個切分互有高低);加權沒有帶來更好的名單品質,卻讓規則從「數這位客戶命中幾個旗標」變成「把四個旗標各乘一個係數再相加」,透明度下降。M4 模型 A 的勝算比排序(低活躍 21.4 > 零動用 6.0 > 淺關係 5.1 > 高聯繫 4.4)保留作為「客戶同時命中兩個旗標、只能先做一種動作時」的動作優先順序參考(例如:當一位客戶同時命中兩個旗標、只能先做一種動作時,先做勝算比較高的那個旗標對應的動作,例如同時命中低活躍與高聯繫的客戶,先做促進使用、再做服務補救),不用於名單計分。
- 理由三(命中 3 與 4 合併):命中 4 個旗標的客戶只有 74 人,若單獨成一層再與三個價值層交叉,會產生三格各約 20 至 30 人的小格,依 [M2-10] 的小樣本慣例無法判讀;合併後 3+ 層 567 人,最小的一格(3+ × 高)50 人、流失率 88%,可依小樣本慣例,做出「流失率極高」的定性結論。合併的代價是損失一個細分層(命中 4 的 98.67% 與命中 3 的 80.49% 看不出差別),此代價可接受,因為動作設計不需要這個差別:流失率 80% 與 99% 的客戶都是「必須立即處理的客戶」,業務單位不會對兩層設計兩套動作;若未來某個動作的成本高到只能給最高風險的幾十位客戶,再把命中 4 的 74 人單獨拉出來即可。
- 理由四(價值軸用交易金額三分位,待驗證事項 #22 定案):本資料集沒有利潤、手續費等直接的價值欄位,交易金額是與客戶貢獻最直接相關的可觀察量,且 M3 T4 已確認交易金額能區分流失與留存客群(中位數 2,329 vs 4,100)。切三層的理由是三層足以區分高、中、低三種投放強度,切四層或五層會使矩陣變成 16 或 20 格、部分格子人數不足;依人數等份切分的理由是三層人數相同(各約 3,376 人),比較各層的流失者人數才公平,且不需要外部提供「年消費多少元算高價值」的標準(因為是用固定人數切分,不是用固定金額切分)。
- 否決方案:固定金額切法(例如年消費 5,000 元以上算高價值):三層人數會不均,且本案沒有「多少元算高價值」的外部標準;若 M8 之後要把價值層變成長期規則,再改為固定金額,並定期檢視「這個固定金額切出來的三層人數比例是否仍接近原本的三等份均分人數比例」,因為客戶組成或消費水準改變後,同一個金額對應的人數比例會改變,若無定期檢視,就會讓高價值層越來越大或越來越小。
- 限制一(系統性低估):交易金額欄位是近 12 個月的彙總值,中途流失的客戶因使用期間縮短,交易金額偏低,部分應屬搶救區的客戶可能被歸入低成本區,搶救區的實際規模可能大於矩陣顯示的 426 人。此偏差方向固定(只會低估),是系統性偏差而非隨機變異的雜訊;現有資料沒有每筆交易的日期,無法還原流失前的正常消費。處置:判讀時明寫此偏差;對低成本區中「命中 3+ 且交易金額接近 4,476 元」的客戶,是否放寬進搶救區由業務單位依當期的人工聯繫餘裕決定,本模組不預先決定。
- 限制二(邊界由資料決定):2,567 元與 4,476 元是這一萬名客戶的三分位,換一批客戶邊界就會改變;本模組的目的是「在這一批資料上排出投放優先順序、比較四個策略區」,等份切法讓三層人數相同,比較各層的流失率與流失者人數時不受人數差異干擾,在這個目的下最公平。
- 限制三(隱含假設):以交易金額代理價值,隱含「銀行的利潤主要來自刷卡手續費」的假設;搶救區 86.6% 的客戶命中「零動用旗標(循環欠款(本金)為 0)」,若銀行的利潤主要來自循環利息,這些客戶對銀行的貢獻很低,不應優先投入人工挽留;此時價值軸應改用「循環欠款(本金)」分三層,四區人數與第 6 節判定 (2) 的比較都須重算。銀行實際的利潤結構須由業務單位確認。

### [M5-3] 結論:挽留名單不採「命中 ≥3」或「命中 ≥2」的單一門檻,而是「以矩陣分層投放」:以「命中 ≥2 層」為名單範圍(2,476 人,涵蓋全體流失者的 72%),「命中 3+ 層」與「高價值層」優先,人工聯繫只用於搶救區 426 人,預算不足時先暫緩投放「命中 2 × 低價值」的 1,093 人(挽留名單縮至 1,383 人後,此名單仍能涵蓋 43% 的流失者)。名單圈選方式預設採 C3-b 規則,模型 B 為升級選項,切換條件為:當「每期投放總成本 × 17.4% > 模型維護成本」時,改採模型 B 圈選 (模型 B 圈選與規則圈選的差異,見理由四說明)。效益以情境試算呈現:挽留成功率假設 10%、20%、30% 三個情境,把「每人投放成本」當作「1 單位」。

- 理由一(用「每留住一人的成本」來比較各方案的有效程度):待驗證事項 #9 與 #25 都不能只看精確率回答,因為精確率高的名單人數少、留住的總人數也少;必須把「名單有多準」、「名單範圍有多大」、「每個客戶的價值」放在同一個尺度上比較,這個尺度是「每留住一位客戶的成本」= 每人投放成本 ÷(名單精確率 × 挽留成功率)(這是由「投放總成本 ÷ 預期留住人數」化簡而得的公式,化簡過程中,名單人數會相除消掉)。投放總成本只隨名單人數變動,不能反映名單本身有沒有效,故不能用「投放總成本」比較各方案的有效程度。
- 理由二(情境試算,不填單一預估值):挽留成功率與每人投放成本在本資料集都不存在,只能靠實際投放或 M6 實驗測出;實務做法是把缺少的數字當成可調整的輸入值:成功率設三個情境各算一次,每人投放成本留在答案裡當單位,亦即,把結果寫成「每留住一人要花幾倍的每人投放成本」(命中 ≥3、成功率 20%:1 ÷(0.829 × 0.2)= 6.0 倍,表示「每留住一人要花 6.0 倍的每人投放成本」)。決策者依業務經驗(例如過去挽留活動的實際成效)選定最可能的成功率情境(表中 10%、20%、30% 三欄之一),再把該欄的倍數乘上業務單位實際的每人投放成本(例如每人 500 元),即得出「以元計的每留住一位客戶的成本」(命中 ≥3、成功率 20%:6.0 × 500 = 3,000 元),比較哪個名單方案比較符合成本效益;把「數字是怎麼算出來的」與「哪些數字是假設的」都攤開來看,決策者就能自己代入實際數字,結論不會因為分析者猜錯成本而發生錯誤或失效。
- 理由三(門檻取捨,待驗證事項 #9 定案):成功率 20% 時,命中 ≥3 名單(567 人、精確率 82.9%)每留住一人要花 6.0 倍的每人投放成本,命中 ≥2 名單(2,476 人、47.3%)10.6 倍;當門檻收緊,精確率上升、每留住一人的成本下降,但名單內流失者從 1,171 人減為 470 人,留住的總人數跟著減少,這是精確率與召回率的取捨在成本上的表現。**最後決定「(a)名單範圍取命中 ≥2 」的理由**:命中 2 這一層 1,909 人、流失率 36.72% 仍遠高於基準流失率 16.07%,若門檻設在命中 ≥3,命中 2 這一層的 701 位流失者就會因此收不到任何挽留動作。**(b)同一筆預算在命中 ≥2 的大名單中,優先投在命中 3+(每留住一人的成本最低)與高價值層(能保留的年消費最多)**:搶救區每留住一人 13.1 倍高於低成本區 10.2 倍,但搶救區平均年消費 7,930 元是低成本區 2,202 元的 3.6 倍,換算「每一單位投放成本能保留的年消費」為 605 元對 216 元,約 2.8 倍(兩區每人投放成本皆當 1 單位的前提下);這說明**比較方案時不能只看單位成本,必須同時看客戶價值**,也是矩陣需要價值軸的原因。**(c)預算不足時先暫緩 2 × 低的 1,093 人,因為該格在 4.3 的優先順序最低**(該格每位客戶平均會流失的年消費 ≈ 765 元);暫緩後涵蓋率由 72% 降為 43%,即該格 465 位流失者(占全體 29%)不會收到挽留動作,決策者可依預算在 2,476 人與 1,383 人之間選擇。(詳見 Cell M5-12 第 6 節判讀 意涵 (1) 小結)
- 理由四(預設使用「規則」圈選名單、模型 B 是「升級選項」,待驗證事項 #25 定案):同一測試集、同樣 703 人名單規模下,C3-b 規則精確率 46.5%、模型 B 精確率 56.3%,每留住一人的成本:模型 B 是規則的 82.6%(0.465 ÷ 0.563),即模型 B 節省 17.4%;兩方案的成本相除時成功率抵消,可知「此比例與成功率無關」。切換條件「每期投放總成本 × 17.4% > 模型維護成本」不需要成功率,決策者只要有「投放總成本」與「模型維護成本」這兩個數字就能判斷,決策者少一個要猜測的參數(未知的成功率),決策就更穩健可靠。**待驗證事項 #9 決定名單規模設多大、哪些客戶優先,#25 則決定用什麼方法把名單挑出來**;**改用模型 B 只換「挑到誰」,不換「挑幾個」,名單規模與價值軸不變**。(細節說明:若模型與 C3-b 規則要公平比較,兩者必須在同一群 3,039 人上計算,作法就是:先在測試集 3,039 人裡用規則圈出命中 ≥2 的 703 人(精確率 46.5%),再讓模型 B 從同樣 3,039 人裡取流失機率最高的 703 人(56.3%)。兩份名單來自同一群人、人數相同,唯一的差別是「挑到誰」,所以 9.8 個百分點的差距只反映「挑人方法的好壞」,沒有混進其他因素(Cell M5-11.0 第一步「五、」)。)
- 否決方案:(1) 圈選條件使用「單一門檻命中 ≥3」:雖然每留住一人的成本最低,但有 701 位命中 2 的流失者無法收到任何挽留動作;(2) 直接採模型 B 圈名單:本資料集無法證明「多出的精確率值得付出維護成本」,且「規則先行不妨礙日後切換」([M5-1] 理由一)。
- 限制:(1) 本節的倍數只能比較方案優劣(優劣順序只由精確率決定,不因成功率改變),**不能算出實際金額**,要算實際金額須有 M6 測出的成功率與業務單位提供的每人投放成本;(2) 倍數只能在各方案每人投放成本相同的前提下互相比較,搶救區(人工)與低成本區(自動化)的每人投放成本不同,換算金額時兩區要分別乘上該區的每人投放成本(例如:「人工 500 元、推播 5 元」試算:6,550 元對 51 元),2.8 倍(搶救區的「每一單位投放成本能保留的年消費」約是低成本區的 2.8 倍)不是兩區實際的成本效益差距,但不改變「搶救區用人工、低成本區用自動化」的定案(因為搶救區每留住一人雖然要花 6,550 元,但仍低於搶救區客戶年消費 7,930 元,因此人工聯繫的成本是可負擔的);(3) 17.4% 這個使用模型 B 的節省比例(切換條件的數字),只適用於命中 ≥2(703 人)的名單規模。當名單規模越小,規則挑到的本來就是最明顯的高風險客戶,模型 B 相比規則能多挑對的空間越小(例如: 178 人規模時,使用模型 B 的節省比例為 6.3%)。其他名單規模的情形,必須重算切換條件;(4) 切換條件所需的「每期投放總成本」與「模型維護成本」在本資料集都沒有,因此本節只能以公式型態呈現(即本節只列出判斷式「每期投放總成本 × 17.4% > 模型維護成本」,不代入數字下結論;決策者取得兩個數字後代入即可判斷,例如每期投放總成本 1,000,000 元時,改用模型 B 每期省 174,000 元,模型維護成本 100,000 元時切換、模型維護成本 300,000 元時不切換,Cell M5-11.0 結果 (3))。

### [M5-4] 結論:k-means 以七個行為變數(交易筆數、交易金額、循環欠款(本金)、往來產品數、客服聯繫次數、不活躍月數、交易筆數變化比)標準化後分群,手肘法取 k = 4(random_state = 42、n_init = 10),群依流失率由高到低重新命名為 A 至 D。A 群 2,658 人、流失率 42.1%,涵蓋矩陣命中 3+ 的 93%(527 ÷ 567)與命中 2 的 53%(1,014 ÷ 1,909),但混入 1,117 人命中 ≤1 的低風險客戶;k-means 四群的區分力(2.7% 至 42.1%)低於矩陣 12 格(notebook 第 3 節 [S1] 矩陣)的區分力(0% 至 88%),且群無法寫成名單條件,故不使用 k-means 圈選挽留名單,只作「演算法分群與規則式分群結論一致」的旁證。

- 理由一(輸入變數):七個變數取自 M4 第 8 節結論 2,即模型 B 同時控制所有變數後「效果顯著且穩定的七個行為變數」;本節的目的是「對照規則式分群」,「給 k-means 的七個變數」與「矩陣四個旗標」所用的欄位同屬「客戶的行為欄位」,且都來自 M2 假設樹的行為枝與 M4 模型 B 確認有效果的變數;兩種方法使用同一類資訊,區分力的差異才能歸因於「分群方法不同」,而不是「使用的資訊不同」,比較才公平(若 k-means 用了矩陣沒用的資訊(例如人口屬性),或少了矩陣用的訊號,區分力的差異就可能來自「用的資訊不同」,而不是「分群方法不同」,對照就失去意義)。**演算法不放「人口屬性變數」**:M4 已證明人口屬性變數對流失的影響效果小,放入會讓群的意義變成「人口輪廓」而非「行為輪廓」,無法對應任何動作(因為是觀察客戶行為,再設計對應的挽留動作),且放入人口屬性變數會「稀釋有效變數的影響」、縮小群與群之間的流失率差距(k-means 對所有變數一視同仁算距離,客戶可能因為在年齡、性別等與流失無關的變數上相近而被分到同一群,即使在與流失有關的變數上差很多,同一群因此混入流失率高與低的客戶,群的平均流失率被拉平)。**演算法不放 is_churned 欄位資訊**:k-means 是非監督式方法,若放入這個答案欄位,演算法會直接依這一欄切開流失與未流失客戶,等於用答案驗證答案,原本目標的「行為變數本身有沒有流失結構」的對照就失去意義。
- 理由二(選 k):群內平方和從 k = 2 到 3 下降 12.0%、到 4 下降 8.8%,之後每多一群只下降 6% 至 8%;依「降幅最後一次明顯高於之後各步的 k」取 k = 4。使用手肘法畫出的「群內平方和相對k」的曲線是逐漸變平的(12.0 → 8.8 → 7.6 → 7.9 → 6.8 → 5.8),沒有一處明顯從陡變平,因此「轉折點的判斷有主觀成分」,若取 k = 3 亦屬合理,故判讀寫明依據並檢核 k = 3 的結論是否改變(見檢核)。
- 理由三(判定):A 群流失率 42.1%、D 群 2.7%,顯示「行為變數本身就帶有與流失相關的結構」;但 A 群 42.1% 只相當於「矩陣命中 2 層的水準(36.7%)」,「遠低於命中 3+ 層的流失率 82.9%」,原因是 k-means 依七個變數的整體相似度分群,A 群混入 1,117 人命中 ≤1 的客戶,群的平均流失率被拉平;**矩陣用已驗證的四個旗標直接分層**(四個旗標是 M2 從假設樹行為枝切片結果定義的四個正式流失訊號:低活躍(total_trans_ct ≤ 61)、零動用(avg_utilization_ratio = 0)、淺關係(total_relationship_count ≤ 2)、高聯繫(contacts_count_12_mon ≥ 4);M3 以假設檢定驗證確認淺關係(H4)與高聯繫(H6)的差異不是抽樣波動(低活躍與零動用因差距極大、未另做檢定,[M3-0]),M4 模型 A 確認四個旗標在控制其他旗標後各自仍有效果,勝算比 21.4 / 6.0 / 5.1 / 4.4),區分力更強。C 群(1,240 人,交易金額最高、往來產品數最低、流失率 4.0%,89% 命中 ≤1)對應矩陣的深化區:k-means 在沒有任何旗標定義的情況下也把「高消費、淺關係、低流失」的客戶聚成一群,代表深化區是真實存在的客群、不只是分析者用規則切出來的,是第 4 節對深化區設計交叉銷售動作的獨立資料支持(動作本身有效與否仍由 M6 驗證)。
- 檢核(k = 3 的敏感度):流失率最高的一群為 3,456 人、34.1%,其餘兩群 7.1%、5.6%;34.1% 仍遠高於全體流失率 16.07%(判定一「行為變數本身帶有與流失相關的結構」成立),流失率最高的群也和 k= 4 的 A 群一樣,該群流失率仍遠低於矩陣命中 3+ 的 82.9%(判定二「k-means 的區分力低於矩陣」成立),因此結論方向不變,結論仍是:**k-means 的分群與流失有關,但區分力低於矩陣**。
- 附帶決策(可重現性):固定 random_state 使每次執行 k-means 分群的起始位置相同,分群結果與判讀引用的數字每次重跑都相同(與 M4 固定 random_state = 42 同一目的);n_init = 10 為 scikit-learn 的預設值,用 10 組起始位置各跑一遍取群內平方和最小的一組,多試幾組再取最好的一組,避免結果受到「單一次起始位置的不佳」影響;「群的原始編號」在不同版本或種子下可能不同,因此判讀與第 8 節引用一律以「依流失率重新命名的 A 至 D 群名」為準,比較分群結果是否穩定時,要看「同一批客戶是否仍被分在同一群、該群的人數與流失率是否不變」,不是看群的編號:換種子重跑後,原本的 A 群可能被編為 2 號,但只要成員、人數與流失率都相同,分群結果就是穩定的;若只比對編號,會誤以為結果改變了。
- 限制:k-means 對極端值敏感,交易金額右偏(高價值層從 4,476 元延伸到 18,484 元)會使含極端值的群中心被往高金額方向拉,中等消費客戶可能被改分到別群,造成分群結果偏差;常見處理方式是「先對交易金額取對數再分群」。本模組不處理此問題,因為本案的 k-means 只作對照、不用來圈選名單,故僅列出限制。

### [M6-0] 結論:第一個挽留實驗的母體定為「低成本區命中 3+」的 517 人(sql/05 [E2]:zone = '2_low_cost' 且 hit_count >= 3,即 M5 矩陣「3+ × 低」412 人與「3+ × 中」105 人),歷史流失率 82.4%;搶救區命中 3+ 的 50 人列為第二階段實驗,整個低成本區(命中 ≥2,共 2,050 人)原本列為母體不足時的擴大方案,實作後確認不適合作為解法(見 [M6-3])。待驗證事項 #28 的母體部分於此定案。

- 理由一(為什麼要做實驗,不直接投放後看流失率):直接投放後觀察流失率有沒有下降,無法回答「推播是否能降低流失率」:同一季裡可能同時發生別的事(銀行調整年費、競爭對手推出新卡、整體經濟環境改變),這些事情對所有客戶都有影響,分析者無法把「推播的效果」與「其他事情的效果」分開,這種情形稱為混淆。M3 的檢定與 M4 的模型都是在「沒有人介入」的資料上建立關聯,只能說「兩者有關聯」、不能說「兩者有因果關係」;隨機分組讓分析者自己製造「只差一個條件(是否收到推播)」的兩群人,才能推論「推播 → 流失率」的因果關係。M5 的成本效益試算把挽留成功率設成 10%、20%、30% 三個情境,因為成功率是唯一無法從歷史資料估計的參數,本實驗的目的就是量出真實的成功率,讓三個情境收斂為一個實測數字。
- 理由二(選低成本區命中 3+、不選搶救區的三個理由):(1) 人數:搶救區命中 3+ 只有 50 人,每組 25 人只能偵測到流失率下降約 34 個百分點(成功率約 39%)的效果,M5 的情境 10% 至 30% 全部偵測不到;517 人是三個候選母體中最接近所需人數的。(2) 執行動作的一致性:搶救區的動作是人工聯繫,每位客戶經理的話術、態度、聯繫時間都不同,兩組的差異會混入「由誰聯繫」這個變數;推播是自動化的,每位客戶收到的內容完全一致,兩組之間唯一的差別就是「有沒有收到推播」。(3) 保留對照組的成本較低:對照組要刻意不聯繫,客戶越值錢、不聯繫的機會成本越高;搶救區客戶平均年消費 7,930 元,業務單位通常不願意對他們保留對照組;低成本區每人投放成本低(推播每人約 5 元),而且對照組不投放(刻意不推播)的機會成本較小。第一個挽留實驗選「人數多、通路自動化、單位成本低」的客群,目的是先把實驗流程本身跑通、取得一個可信的成功率,再把方法複製到高價值客群。
- 理由三(以 SQL 重現 M5 的客戶層級表來圈選母體):sql/05 [E0] 以「和 sql/04 完全相同的旗標定義、價值層切法、策略區規則重建客戶層級表」,四區人數必須等於 M5 的 426 / 2,050 / 2,949 / 4,702,確保實驗母體與 M5 名單是同一批人、同一套規則;額外回饋觸發條件(低成本區內消費變化比 < 0.50)在 M5 以 WHERE 條件臨時篩選,M6 要當分層變數,因此做成欄位 extra_reward。
- 附帶決策(歷史流失率只作規劃用基準率):本資料集的 82.4% 是歷史數字,517 人中 426 人在快照時已標記為流失;真正執行實驗時,母體只能是「當時仍為有效客戶」的人,圈選條件須加上 attrition_flag = 'Existing Customer',他們一季內的流失率必然低於 82.4%(歷史流失率的分子是所有已經走的人,實驗期間一季內會走的只是仍在客戶中的一部分)。但「attrition_flag = 'Existing Customer'」這個條件不能套用在本快照上,因為套上去會只剩 91 人、全部未流失(流失率 0%),沒有規劃意義;所以本模組(實驗設計)以歷史流失率當規劃用基準率,並寫明真實實驗開始前「須以當期資料重算基準率與樣本數」(新增待驗證事項 #33)。

### [M6-1] 結論:實驗只設一個決策指標:主指標為「投放後一季內的流失率」,以兩比例 z 檢定(雙尾,α = 0.05)檢定並報告 95% 信賴區間與勝算比;次要指標(一季內平均交易金額、一季內平均交易筆數)與護欄指標(一季內平均客服聯繫次數,實驗組不得高於對照組的 1.2 倍)只描述、不做正式檢定;因此檢定次數為一,α 維持 0.05 不校正。三條決策規則事前寫定。待驗證事項 #23 於此結案。

- 理由一(為什麼只有一個決策指標,回應 #23):每做一次檢定就有一次誤判的機會;若對多個指標各做一次檢定、只要任何一個顯著就宣稱成功,整體誤判率會升高,這是 M3 第 2 節 2.4 的多重比較問題。M3 的解法是 Bonferroni 校正,代價是樣本數會變大:四個指標中,護欄指標只設門檻、本來就不做檢定,若把主指標與兩個次要指標都列為正式檢定,α 變成 0.05 ÷ 3,每組所需人數會由 390 升為 521 人。業界的標準做法是只讓一個指標承擔決策角色、其他指標只描述,因為「上線與否取決於流失率有沒有下降,不會因為交易金額顯著而改變」。這是把 M3 學到的多重比較觀念用在實驗設計上的方式:不是每個指標都要校正,而是「先決定哪個指標需要檢定、哪個指標不需要檢定」。
- 理由二(主指標取「流失率」來觀察):M5 的目標是降低流失;流失是清楚的 0/1 事件,每位客戶在觀察期結束時只有「流失」或「未流失」兩種狀態,流失率 = 流失人數 ÷ 組內人數,任何人計算都得到同一個數字。交易金額這類指標的計算則有歧義(退款是否扣除、極端大額消費如何處理、觀察期起訖如何切)。
- 理由三(次要指標與護欄指標的角色):次要指標解釋機制:主指標只回答「推播有沒有讓客戶留下」,不回答「怎麼留下的」;交易金額是 M5 的價值軸,交易筆數是 M4 模型中對流失影響最大的變數,這兩者回答「留下來的客戶是否還有價值」。護欄指標防止副作用:M2 至 M4 都顯示高聯繫與流失強相關,若推播引發客戶抱怨,聯繫次數會上升,就算流失率下降也不能上線。護欄不做顯著性檢定,因為它回答的是「有沒有變壞到不能接受」這個業務容忍度的問題,不是「兩組是否不同」的統計問題;若改用檢定判定,人數大時連 0.1 次這種業務上可忽略的小幅上升也會顯著,若把護欄的判定規則寫成「護欄顯著 → 不上線」,只要推播讓聯繫次數有一點點上升(任何主動聯繫客戶的動作幾乎都會)、實驗就過不了護欄指標,每個實驗都會被護欄擋下、無法通過;**門檻要檢驗的是「上升幅度有沒有超過可承受範圍」,不是「有沒有上升」**。所以要用「門檻」,不是用「檢定」。
- 理由四(雙尾而非單尾):雙尾檢定較保守,若推播反而使流失率上升(例如推播引起反感),雙尾檢定能偵測到,但單尾檢定的設計不檢視那一側,就偵測不到此種情形;次要理由是與 M3 的兩比例 z 檢定一致(proportions_ztest 預設雙尾檢定)。單尾檢定所需人數雖較少(308 對 390),但對本案的母體缺口沒有實質幫助(因為每組要 308 人,母體 517 人仍然不夠)([M6-3])。
- 附帶決策(護欄門檻 1.2 倍為自訂值):護欄門檻沒有通用標準值,實務上由指標的負責單位依可承受的惡化幅度決定,常見做法是將惡化容忍度定為相對上升 10% 至 20%。本案取 20%: 20% 約為兩組平均值抽樣波動(每組 258 人時約 ±5%)的四倍,不會被隨機差異觸發 (門檻訂定原則:門檻要高於抽樣波動、又要在業務可吸收範圍);母體平均聯繫次數約 3.7 次,1.2 倍即約 4.4 次,恰好跨過本案「高聯繫」旗標的 4 次門檻,若推播讓實驗組越過這條線,代表推播把客戶推向了本案定義的高風險行為。1.2 倍為自訂值,計畫書標明「此指標待客服單位依人力負荷確認」。
- 附帶決策(三條決策規則,實驗結束後依此判定方案是否上線,不再另外加其他判定條件):(1) 主指標顯著且護欄未惡化 → 上線,並把實測成功率代回 notebook 05 第 6 節公式;(2) 主指標不顯著 → 不上線,次要指標與子群分析的發現寫成下一個實驗的假設,不作為上線依據;(3) 主指標顯著但護欄惡化 → 不上線,先修改動作內容後再實驗。規則 2 在本母體下的補充解讀見 [M6-3]。
- 限制:次要指標與護欄指標需要執行系統提供觀察期內的交易金額、交易筆數、客服聯繫次數,本資料集沒有這些資料,計畫書須載明前述資料需求;子群分析(三層各自的兩組流失率差距)於本案只呈現兩組流失率差距與信賴區間、不做檢定、不據此決策,因為每層只有 95 至 317 人,信賴區間很寬(難以判定流失率變化方向),且三層各比一次等於三次檢定,碰巧顯著的機會增加(多重比較)。

### [M6-2] 結論:隨機化單位為客戶(clientnum);分層變數為價值層(低 / 中)× 加碼觸發條件(是 / 否),每層內以固定隨機種子(RANDOM_STATE = 42)對半分;分析採意圖處理分析。實作後兩項修正:(一) 因 mid_reward 層只有 3 人,四層合併為三層(low_base 317 / low_reward 95 / mid 105),實驗組 257 人、對照組 260 人;(二) 平衡檢查十三個變數中 total_relationship_count(SMD 0.144)與 total_amt_chng_q4_q1(0.128)略高於 0.1 的門檻,決定維持分組名單不變、主分析不調整,另預註冊一項以邏輯斯迴歸控制這兩個變數的穩健性檢查。

- 理由一(隨機化單位):推播回饋是個人化的、溢出風險低,資料集也沒有家庭或分行欄位,單位自然是「客戶」;隨機化單位決定了樣本數的計算單位與分析的獨立性假設。
- 理由二(分層變數的選擇與證據):分層的作用是在事前保證兩組在這些變數上的比例相同,避免「隨機分組後,實驗組碰巧多分到一些高風險客戶」;其他變數仍要靠平衡檢查確認分到兩組的比例是否平衡。兩個分層變數都是 M5 已證明與流失率相關、且直接決定 M5 動作設計的變數:(1)價值層:同樣命中 3+,低價值層流失率 85.19%、中價值層 71.43%(M5 矩陣);(2)加碼觸發條件:低成本區內消費變化比 < 0.50 的客戶流失率 72.40%,高於該區整體的 49.2%(M5 第 5 節)。分層變數不是把所有相關變數都納入:分層越多、每層人數越少,實務上分層數通常控制在三到六層。
- 理由三(實作後修正一:四層改三層):sql/05 [E3] 首次執行後,四層人數為 low_base 317、low_reward 95、mid_base 102、mid_reward 3。分層的目的是讓該層在兩組的比例相同;3 人最好的分法是 2 比 1,比例是 67% 對 33%,差 33 個百分點,比例無法相近,所以分層在這一層沒有實質意義,因此依每層至少約 20 人的慣例併入最相近的層(mid_base),合併為 mid 一層 105 人。程式以「每層至少 20 人」的規則(MIN_STRATUM = 20)自動判斷,日後換一批客戶時同一條規則會重新判斷。代價不大,可接受:這 3 位加碼客戶跟著 105 人一起隨機分,兩組最多差 3 人,對每組 258 人流失率的影響最多 3 ÷ 258 ≈ 1.2 個百分點,遠小於 MDE 8.2 個百分點,可接受;本次實驗分組實際為 2 比 1。要分清楚的兩件事:合併改的只是「分組的手法」;而「誰收到加碼版」的動作規則完全不變,實驗組裡消費變化比 < 0.50 的客戶不分價值層一律都會收到加碼版推播。這個調整在實驗設計的實務意義是「先圈選客戶、再定分層」:分層變數在設計時看起來合理,實際圈選客戶後才知道某一層人數太少,這也是本模組將「先跑 SQL、數字先核對、再寫 notebook」作為實作順序的原因之一。
- 理由四(實作後修正二:平衡檢查兩個變數偏高的處理):十三個變數(歷史流失標記、加碼條件、M4 第 8 節結論 2 的七個行為變數、消費變化比、命中數、年齡、性別)中十一個 |SMD| < 0.1;最關鍵的歷史流失標記(0.025)平衡,代表兩組過去的風險水準相當。兩個變數偏高是隨機分組的正常現象(每組約 258 人時,SMD 的抽樣波動約 0.088,0.144 約為它的 1.6 倍,十三個變數中出現兩個並不異常),但 total_relationship_count 是 M3 證明與流失相關的變數,不能只以隨機帶過:這個變數實驗組的平均值 2.85 高於對照組的 2.63,若不處理,實驗組可能因為往來較深而流失略少,這一小部分差距會被誤認為推播的效果。處理方式是「預註冊一項穩健性檢查」:主分析仍是未調整的兩比例 z 檢定,上線與否原則上以此為準;另以 M4 的邏輯斯迴歸再分析一次(結果變數為「是否流失」,解釋變數為「是否在實驗組、分層、total_relationship_count、total_amt_chng_q4_q1」),報告同時列出兩個結果;兩者結論一致時結論穩固,若主分析顯著而調整後不顯著,代表效果有一部分可能來自兩組在這兩個變數上的差異,決策傾向保守,以迴歸調整後的結果作為上線判斷的依據。事前寫定主分析是什麼且不調整,才不會變成「事後挑選結果較有利的分析方法」。
- 理由五(意圖處理分析):分析時依「被分到哪一組」分組,不依「有沒有真的收到推播」分組。推播發出後會再發生一次篩選,能收到推播的通常是還在用 App、還在接電話、本來就比較不會流失的客戶;若只拿真的收到的人與對照組比,隨機分組所消除的選擇偏誤會在「送達」這一步重新產生。意圖處理分析測出的兩組流失率差距會小於只看「真的收到的人」算出的差距,但這個較低的數字(兩組流失率差距較小)才是方案上線後實際可預期的效果,因為真正上線時也一定有客戶收不到推播。

### [M6-3] 結論:MDE 由 M5 的成本效益試算反推:MDE = 基準率 82.4% × M5 最低情境的成功率 10% ≈ 8.2 個百分點(目標流失率 74.2%);α = 0.05 雙尾、檢定力 0.8;以 statsmodels NormalIndPower 計算(方法同 M3 第 8 節),每組需 390 人、合計 780 人,母體 517 人(每組 258 人)不足。定案為母體全部納入 (517 人)、對半分,計畫書如實載明「在檢定力 0.8 下可偵測的最小效果為 10.3 個百分點(成功率 12.5%);對規劃的 8.2 個百分點檢定力只有 0.63」,以「分批累積至每組 390 人」為補救方式,不放寬 MDE、不擴大母體、不改單尾。觀察期一季,結束後一次判讀,中途不判讀。實作前的公式規劃錯誤已於實作後修正:規劃階段以公式試算得每組 197 人,此為公式誤用,已修正。

- 理由一(MDE 由業務問題決定,不由母體決定):實驗是為了回答業務問題,MDE 的設定來自業務問題,人數是為了回答問題而付出的代價;順序是「業務問題 → MDE → 算出人數 → 對照母體 → 不足再調整」,不是「先看母體有多少人,再決定能測多小的效果」。M5 試算裡最小的情境是 10%,實驗要能回答「效果至少有沒有 10%」,M5 的三個情境才能被一個實測數字取代;若實驗連 10% 都偵測不到,「沒有顯著差異」會同時與「效果為 0」和「效果在 0 至 10% 之間但人數不足以偵測」相容,資料無法區分兩者,M5 的試算就得不到任何可代入的數字(三個情境仍停留在假設,試算就無法收斂)。成功率 10% 不等於「流失率降 10 個百分點」:成功率的定義是「本來會流失的人裡被留住的比例」,降幅 = 基準率 × 成功率 = 82.4% × 10% ≈ 8.2 個百分點。
- 理由二(實作後修正:197 人是公式誤用):規劃階段以公式試算得每組 197 人、認為 517 人「足夠且留有餘裕」,並寫進 notebook 初稿;Cell M6-6 以 statsmodels 算出每組 390 人,核對後確認規劃階段試算時誤用了「一組與固定數字比較」的公式,兩組比較所需的人數為其兩倍(以 Cohen 原表 h = 0.20 → 392 人,與 M3 Cell M3-19 用同一函式算 h = 0.120 得 1,092 人交叉確認,M3 的數字沒有錯);1,000 次模擬的檢定力只有 0.63(若 197 人是正確值,每組 258 人應得到 0.85 以上),再次證實此規劃錯誤。這個錯誤「不改變實驗對象、分層、分組、分析計畫與決策規則」,改變的是「計畫書對可偵測效果的陳述與決策規則 2 的解讀」。從這個錯誤得到的教訓:樣本數公式有多個版本(一組對固定值、兩組互比、單尾、雙尾),以 statsmodels 套件的計算為準、再以獨立來源交叉核對(Cohen 原表、M3 的既有計算),自行以公式試算只用來預估人數的量級(例如:幾十人、幾百人還是上千人),正式數字以程式計算為準;若未經程式核對就把 197 人寫進計畫書,最可能的後果是「推播真的有效,實驗卻判定不顯著」,而且實驗結果本身無法分辨「不顯著」是「推播效果不存在」還是「樣本數(人數)不足」。
- 理由三(母體不足的解法,四個選項的取捨):(1) 擴大母體為低成本區命中 ≥2(2,050 人):否決:基準率降為 49.2%,成功率 10% 對應的降幅縮為 4.9 個百分點,每組需 1,615 人,2,050 人同樣不足;即使全部納入(每組 1,025 人),可偵測的 6.2 個百分點換算成功率仍是 12.5%:絕對降幅變小了,但「可偵測的最小成功率」(相對效果,即降幅 ÷ 基準率)沒有改善,因為基準率也跟著降了;且命中恰為 2 的客戶在 M5 名單總表(notebook 05 第 8 節, 依優先順序排列)是第 4 列、命中 3+ 是第 3 列,擴大母體等於把 M5 優先順序不同的兩列混在同一個實驗。(2) 改單尾檢定:否決:每組 308 人仍不足(檢定力 0.74),且雙尾較保守並與 M3 一致。(3) 把規劃成功率改為 12.5% 讓 517 人剛好足夠:否決:這是反過來「先看母體有多少人,再決定能測多小的效果」,10% 至 12.5% 之間的效果從此偵測不到,而這一段正是 M5「最低要有多少才值得做」的區間,若改為 12.5%,本實驗就不是在回答 M5 的問題。(4) **最後決定採此方案:維持 517 人全部納入、如實陳述可偵測效果、分批累積**:所需人數 390 大於每組 258,母體本來就要全部納入,推播為自動化,全部納入不增加執行成本;若業務單位要求偵測到 10%,就採用分批累積方式:「下一季把新產生的命中 3+ 客戶依同一條規則納入第二批,累積到每組 390 人再判讀一次」(每批各自分層隨機、各自有對照組,分析時把「批次」當成第四個分層變數,兩組在批次上的比例相同,下一季環境不同造成的差異不會集中在某一組),這是實務上「持續招募直到達到樣本數」的標準做法。
- 理由四(決策規則 2 在本母體下的補充解讀):每組 258 人對 8.2 個百分點的檢定力只有 0.63,「主指標不顯著」有兩種可能:推播沒有效,或推播有 10% 至 12.5% 的效果但本次人數不足以偵測,資料無法區分兩者;因此不顯著時先依補救方式納入下一批客戶、累積到每組 390 人後再判讀一次,若累積後仍不顯著,才依規則 2 不上線。不顯著時不能「再做一次檢定」:因為每做一次檢定就有 5% 的碰巧顯著機率,若「不顯著就重做、顯著才停」,誤判率會不斷累積(偷看問題);分批累積不是重做實驗,而是事前先寫明這個規則,判讀仍只有一次(累積到足夠數量後才做一次判讀)。
- 理由五(期間與不偷看):觀察期一季(約 13 週):消費變化比以季為比較單位,一季是這份資料的自然時間尺度;太短看不到流失,太長則其他因素累積越多、也讓業務單位等太久;一季與銀行的業務週期(季報)一致。推播在第一週內發送完畢,觀察期從發送完畢的隔週起算。結果在一季結束後一次判讀,中途不判讀:若每週判讀、一看到顯著就停止,誤判率會遠高於 5%(偷看問題);中途只監控執行狀況(推播送達率、對照組是否被接觸),不在中途看兩組流失率。
- 檢核(1,000 次模擬驗證檢定力):假設推播真的有 10% 的效果,用程式對實際分組名單重複「製造結果、跑檢定」1,000 次,主指標顯著的比例為 0.632,statsmodels 的理論值為 0.626,兩者相差 0.006,小於 1,000 次模擬本身約 ±0.03 的抽樣波動,視為一致;代表樣本數公式、分析程式、分組名單三者互相吻合,也代表分層對半分(本實驗分組方式)沒有違反公式「兩組獨立、人數相同」的假設,因此第 4 節的樣本數計算可直接套用在第 5 節的名單上(限制 (2) 的依據)(細節補充說明:第 4 節算 390 人時用的公式假設「兩組獨立、人數相同」;本案分組是分層對半分,不是單純隨機。模擬值 0.632 與理論值 0.626 吻合,代表分層沒有讓公式失效,第 4 節的數字可以直接套在第 5 節的名單上)。
- 限制:(1) 基準率 82.4% 是歷史流失率,實驗期間的基準率必然比歷史流失率低,相同成功率對應較小的降幅,所需人數會再增加,母體不足的程度會擴大;實驗前須以當期資料重算,處理方式相同(如實陳述可偵測效果、分批累積),不放寬 MDE、不擴大母體(待驗證事項 #33)。(2) 樣本數計算方式是「假設兩組人數相同且各觀察值獨立」;分層隨機分組不改變這個計算方式(分層只影響分組方式,不影響每組人數),回應待驗證事項 #23「分層隨機化時調整計算方式」:「本案的分層是對半分,不需要調整計算方式;若未來改為兩組人數不同(例如實驗組 70%、對照組 30%),solve_power 的 ratio 參數要改,所需總人數會上升」。

### [M6-4] 結論:本模組的範圍界定如下。(一) 分析計畫在資料回來前寫定(預註冊),並以模擬資料跑通:四張報告表格(主指標、次要與護欄指標、子群分析、代回 M5 公式)與三條決策規則在資料回來前就固定,所有模擬輸出標示「底線 + SIM」,模擬只證明分析程式能執行、輸出格式正確,不證明推播有效(因為都是模擬資料,不是依據真實資料得出的實驗結果)。(二) 實驗產出的用途:真實實驗結束後,以兩組的實際流失率算出實測成功率 s = (p_c − p_t) ÷ p_c,代回 notebook 05 第 6 節公式 1 與公式 3,使 M5 的三個情境收斂為一組數字(第 6 節以模擬資料算出的 s = 11.8% 只用來示範表格格式,不是測量值)。(三) 「調高信用額度」另開第二個實驗、本模組只寫實驗設計草案,不併入第一個實驗、不做多組實驗或因子設計;搶救區列為第二階段實驗。待驗證事項 #11(M6 部分)狀態改為「待第二個實驗驗證」,不結案。

- 理由一(預註冊與模擬的定位):在資料回來之前就把分析方法寫定,目的是避免事後看到結果才挑一個「剛好顯著」的方法。本資料集沒有實驗結果,第 6 節用程式「製造」一份結果(對每位客戶依指定的機率隨機抽出 0/1:對照組依所在分層的歷史流失率,實驗組依歷史流失率 × (1 − 假設成功率 10%)),把分析流程從頭跑到尾;真實資料回來後只需把四個模擬欄位(churn_q1_SIM、trans_amt_q1_SIM、trans_ct_q1_SIM、contacts_q1_SIM)換成執行系統提供的觀察期實際值,其餘程式不變。唯一有推論意義的是 1,000 次模擬的檢定力交叉驗證([M6-3] 檢核);單次模擬的 p = 0.0057 是分析者設定 10% 效果後抽出來的,不能用來推論推播的真實效果。「單次模擬的數字不具推論意義」:那一次模擬的 p = 0.0057 是分析者自己設定 10% 效果後抽出來的,它不證明任何關於推播的事;有推論意義的只有 1,000 次的比例(驗證檢定力:假設推播真的有 10% 的效果,用程式重複「製造結果、跑檢定」1,000 次,數有幾次判定顯著;這個比例就是實際分組下的檢定力,拿來與 statsmodels 用公式算出的理論值比對,兩者一致代表「樣本數公式、分析程式、分組名單」三者互相吻合。本案兩者都約 0.63,低於慣例的 0.8,原因是每組 258 人低於所需的 390 人)。
- 理由二(成功率的換算用對照組實測值):p_c 是對照組在觀察期結束時的實際流失率(代表「若沒推播動作,本來會流失的比例」),p_t 是實驗組的實際流失率,兩者的差是「被留住的比例」,相除就是 M5 定義的挽留成功率;用對照組實測值而不用歷史流失率 82.4%(歷史流失率只在第 6 節造模擬資料時當抽樣機率用),因為實驗期間「本來會走的比例」就是對照組測到的那個數字。將 s 代回 notebook 05 第 6 節公式 1 與公式 3 後,加上「業務單位提供的每人投放成本」,M5 第 6 節的七個方案能從倍數換算成金額,達成待驗證事項 #28 要求的「使成本效益試算收斂為一組實測數字」(新增待驗證事項 #34)。
- 理由三(調高信用額度只寫實驗草案的三個理由):(1) 效果大小沒有依據:第一個實驗的預期效果可以從 M5 的精確率與三個成功率情境推出合理範圍;調高額度的預期效果在本資料集沒有任何可作為效果大小假設的數字,M4 模型 B 甚至顯示信用額度在控制其他變數後不顯著(勝算比 0.94、p = 0.32)(補充說明:在這種情況下若憑空指定一個效果大小(例如假設「調高額度,流失率能降 5 個百分點」)去算樣本數,算出的人數沒有依據,寫進文件反而降低可信度;實務上的做法是先用第一個實驗測出「挽留動作在這類客群大概能有多大效果(成功率是多少)」,再拿這個數字當第二個實驗的效果大小假設(MDE = 第二個實驗母體的基準率 × 實測成功率),據此算樣本數)。(2) 母體與執行條件欠缺關鍵欄位:哪些客戶可以被調高信用額度,取決於授信單位的信用評分與風險政策,本資料集沒有這些欄位,無法圈出母體就沒有樣本數。(3) 邊際價值低:完整設計第二個實驗只是把 notebook 06 的大部分章節再做一次,依「資料不足以支持完整設計時,只做到資料允許的程度並寫明缺少什麼」的原則,本模組呈現第一個實驗的完整設計,第二個實驗只寫一份說明「為什麼現在不能設計完整、需要什麼條件才能設計」的草案。草案的候選母體取「零動用旗標客戶」(sql/05 [E4]:搶救區 369 人、流失率 33.1%、平均額度 10,639 元;低成本區 1,250 人、58.0%、7,777 元),搶救區零動用客戶的信用額度最高卻仍流失,呼應 notebook 02 C4「信用額度只是關係深度的痕跡」的機制,但這只是觀察、不是驗證(因為還沒實際做實驗來驗證)。
- 理由四(不併入第一個實驗):若綁在同一個方案裡(實驗組:收到推播 + 調高信用額度),實驗組的流失率下降時無法歸因給推播或調高信用額度;若分成多組(多組實驗,multi-arm test),例如:對照組、只推播組、只調高額度組、甚至加一個「推播 + 調高額度」組(此種組合為「因子設計(factorial design)」),會把同一母體切成三、四份,每組人數變成原來的三分之一或四分之一,notebook 06 第 4 節的樣本數更不夠;而且調高信用額度需要授信核准、每位客戶核准的額度不同,無法像推播那樣「每個人收到一樣的東西」。實務慣例是「一個實驗只回答一個問題」:因子設計通常用於同一通路、同一單位能控制的兩個小變化(例如:推播文案 A/B × 發送時段早/晚),不用於「推播」與「更改授信額度」這兩種性質完全不同的動作上。
- 附帶決策(風險清單寫進計畫書):五項風險(對照組被污染、新奇效應、基準率與歷史不同及母體不足、中途偷看、推播未全部送達)與預防方式,以及兩項補充(母體內客戶被排除時兩組應以同一條規則排除;推廣到命中 2 的客群前應再做一次實驗或分階段上線),全部寫進 docs/06_experiment_plan.md §9。
- 限制:(1) 本模組(M6)是實驗設計,不是實驗結果:所有流失率都是歷史數字,所有「投放後」的數字都是模擬;M8 引用本模組時只能說「已設計實驗」,不能說「本實驗已驗證方案有效」(新增待驗證事項 #36)。(2) 模擬假設每位客戶的流失結果互相獨立、且推播在每一層的成功率都是 10%;真實情況可能是收到加碼版那一層的流失率降幅更大,這正是子群分析要看的差異,但模擬的效果是分析者設定的,無法呈現。(3) 次要指標與護欄指標的模擬值是以資料集既有的 12 個月欄位 ÷ 4 換算的替代值(因為一年分成四個季度),只為了讓程式能執行到表格輸出,但這都是模擬資料,在真實資料回來前不能對這兩種指標做任何判讀。(4) 第二個實驗的完整設計需要三項輸入:授信單位的調高信用額度資格規則與幅度、第一個實驗的實測成功率、風險控管單位的核准(新增待驗證事項 #35)。
